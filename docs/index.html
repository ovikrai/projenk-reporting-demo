      01 / THE PROBLEM

      Reporting should be repeatable.

      Manual spreadsheets make it easy to overlook duplicates, mix refund rules and send figures nobody can trace. This demo makes each assumption visible and each output reproducible.

      02 / THE SOLUTION

      Small pipeline. Complete handoff.

      A Python standard-library pipeline validates each row, uses decimal currency arithmetic, compares months and generates a standalone executive report plus a MIME email attachment.

      Designed to be inspectable

      • Reproducible input with a fixed random seed
      • CSV exports and row-level rejection reasons
      • Monthly comparisons and documented formulas
      • Explicit email delivery and duplicate-send receipts
      • Tests for edge cases, reports and delivery
      • Static hosting on GitHub Pages

      Know what you’re looking at

      All orders, revenue and business observations are synthetic. The dashboard reads reports produced by Python. On GitHub Pages, the pipeline button replays those stored artifacts. When served with python3 main.py, it runs the Python pipeline again. Email previews use fictional addresses; real delivery requires SMTP credentials outside the repository.

      Revenue includes completed orders after discounts. Refunds and cancellations contribute zero revenue and zero cost. Gross margin excludes operating expenses. Comparisons use the full previous calendar month; July has no baseline. Data quality counts describe all three months.
